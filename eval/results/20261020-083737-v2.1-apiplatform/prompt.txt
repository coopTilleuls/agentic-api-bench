# Change request

The API in this directory implements the bookshop specification included below. Change it as follows. Everything not mentioned here must keep working exactly as specified.

The database has been migrated: `purchase` has a new column `refunded_at` (timestamp, NULL when the purchase was not refunded). You must not change the database structure further.

1. **Customer header.** Customers now identify themselves with the `Customer-Id` header instead of `X-Customer-Id`. `X-Customer-Id` is no longer accepted (a request carrying only it answers 401).
2. **Page count.** Every list also tells the number of pages: `{"items": [...], "total": ..., "page": ..., "itemsPerPage": ..., "pages": <number of pages, 0 when there are no items>}`.
3. **Book page size.** `GET /books` now has 20 items per page unless the client asks otherwise. Other lists keep 10.
4. **Search.** `GET /books?q=herbert` matches books whose title or author name contains the text, case-insensitive. It combines with every other filter, sorting and pagination.
5. **Authors with published books.** `GET /authors?hasPublishedBooks=true` lists only authors with at least one published book, `false` only those without. Any other value answers 400.
6. **Refunds.** `POST /purchases/{id}/refund` refunds one of the customer's purchases:
   - the stock of each book of the purchase increases back by the quantity bought, and the purchase records the refund time;
   - the answer is 200 with the purchase, which now has `refundedAt` (timestamp, or `null` when not refunded) in every purchase response;
   - another customer's purchase or an unknown one answers 404; a purchase already refunded answers 409 and changes nothing;
   - the payment service is not involved.
7. **Report.** Refunded purchases are excluded from `GET /reports/sales`.

# Bookshop API

Build an HTTP API for a bookshop. The data already exists in a PostgreSQL database (connection details are given below). You must not change the database structure.

The API is served on `http://localhost:8089` and must start with `./start.sh`, run from this directory, without any argument. It is stopped by killing that process.

## Data

- `author` (`id`, `name`): `name` may be NULL for anonymous authors.
- `book` (`id`, `title`, `author_id`, `published`, `price_cents`, `published_at`, `stock`): `published` is true when the book is publicly released; `price_cents` is an integer; `published_at` is a date, NULL for unpublished books; `stock` is the number of copies available.
- `customer` (`id`, `name`, `email`).
- `purchase` (`id`, `customer_id`, `created_at`, `total_cents`).
- `purchase_line` (`id`, `purchase_id`, `book_id`, `quantity`, `unit_price_cents`).

## Response format

All responses are JSON unless stated otherwise.

- A list is `{"items": [...], "total": <number of matching items, all pages>, "page": <current page>, "itemsPerPage": <page size>}`.
- An error is `{"error": "<human readable message>"}` with the status code given below. A request with an invalid parameter (unknown sort field, sort direction other than `asc`/`desc`, malformed number, boolean or date) answers 400. Unknown query parameters are ignored. A malformed id in a path (`/books/abc`) answers 404.
- Dates are `YYYY-MM-DD`, timestamps ISO 8601 in UTC, amounts integers in cents.

Pages start at 1 (`?page=2`). Unless stated otherwise a list has 10 items per page; the client may ask for another size with `?itemsPerPage=n`, from 1 to 50 (anything else answers 400). A page past the last one answers 200 with an empty `items`.

## Authors

- `GET /authors`: all authors, `id` order, each with `id`, `name` and `publishedBooks` (the number of their published books).
- `GET /authors/{id}`: one author with `id`, `name` and `books`, the list of their published books as `{"id", "title"}` in `id` order. Unknown author: 404.

## Books

Only published books are visible: unpublished ones are absent from lists and answer 404 everywhere below except `PATCH`.

- `GET /books`: each book has `id`, `title`, `priceCents`, `publishedAt`, `stock` and `author`, the author as `{"id", "name"}`.
- Filters, combinable with each other and with pagination and sorting:
  - `?title=dune`: title contains the text, case-insensitive;
  - `?author=Frank%20Herbert`: author name, exact;
  - `?priceCents[gte]=1000`, `?priceCents[lte]=2000`: price range, bounds included;
  - `?publishedAt[after]=2020-01-01`, `?publishedAt[before]=2020-12-31`: publication date range, bounds included;
  - `?inStock=true`: only books with `stock` greater than 0; `?inStock=false`: only books with `stock` 0.
- Sorting: `?order[priceCents]=asc|desc`, `?order[title]=asc|desc`, `?order[publishedAt]=asc|desc`, several allowed, applied in the order given, ties broken by `id` ascending. Default: `id` ascending.
- `GET /books/{id}`: one book, same shape.
- `PATCH /books/{id}`: partial update of `title`, `priceCents` and `stock`, only the fields sent change. Works on unpublished books too. `priceCents` or `stock` below 0 or not an integer, or a `title` that is null or empty, answers 422 and changes nothing. Unknown fields are ignored. The response is the book in the shape above, or 204 if it is unpublished.

## Purchases

Customers identify themselves with the `Customer-Id` header. Without it, or with an unknown or malformed customer id, every request below answers 401, checked before anything else. A customer only ever sees their own purchases: another customer's purchase answers 404.

- `GET /purchases`: the customer's purchases, most recent first, each with `id`, `createdAt`, `totalCents` and `lines`, each line `{"bookId", "title", "quantity", "unitPriceCents"}`.
- `GET /purchases/{id}`: one purchase, same shape.
- `POST /purchases` with `{"lines": [{"bookId": 1, "quantity": 2}, ...]}` buys books:
  - `lines` must not be empty, and every line must reference a published book with an integer quantity of at least 1, otherwise 422;
  - every book must have enough stock for the total quantity asked across all lines, otherwise 409;
  - the unit price is the book's current price, the total is the sum of the lines;
  - the payment service (below) must accept the payment: declined answers 402; unreachable, failing or any other answer gives 502;
  - on success the purchase and its lines are stored, the stock of each book decreases by the quantity bought, and the answer is 201 with the purchase in the shape above;
  - on any failure, nothing is stored and no stock changes.

## Payment service

An external service, already running, accepts or declines payments: `POST http://127.0.0.1:18090/payments` with `{"customerId": <id>, "amountCents": <total>}` answers `{"status": "accepted"}` or `{"status": "declined"}`.

## Sales report

- `GET /reports/sales?from=2026-01-01&to=2026-01-31` downloads a CSV file of the books sold between those dates (purchase `created_at`, bounds included, whole days in UTC). Columns, in this order: `title`, `quantity`, `revenueCents`. One line per book sold in that period, sorted by `revenueCents` descending, then `title`, then book id, with a header line. `from` and `to` are required: missing, malformed, or `from` after `to` answers 400. The report is public and covers all customers.
